# ViCons — UI 設計規格 v1.0

**日期**：2026-09-19
**狀態**：待審批
**範圍**：合併 ViConst（工程算量 hub）+ VicBid（投標管理）為單一桌面優先應用
**技術約束**：維持零構建 vanilla（原生 ES + 單一 HTML 入口 + IndexedDB），無 npm、無打包

---

## 0. 這份規格解決什麼

現在磁碟上有兩個前端，視覺語言互相衝突：

| | ViConst | VicBid |
|---|---|---|
| 底色 | 深色 HUD `#0a0e17` | 淺色 Tailwind `#f8fafc` |
| 導航 | 頂欄 4 個水平分頁 | 側邊欄 13 項分組 |
| 強調色 | cobalt `#3b6ef0` | oklch 四色系 |
| 版面 | 單欄，少量卡片 | 側欄 + 內容區 |
| 檔案量 | index.html 369 行、app.js 737 行 | index.html 398 行、11 個 view 檔共 1,410 行 |

合併後如果放任兩套並存，結果是使用者每切一次頁就換一次視覺世界，且元件會分裂成兩份要各自維護。

**本規格的做法**：以 ViConst 深色 HUD 為唯一語言，把它從「4 分頁的 hub」升級成「有完整元件庫的應用外殼」，再讓 VicBid 的 11 個模組在新版面上重做。

---

## 1. 設計原則（依優先序）

1. **圖紙優先** —— 工程圖與量測畫布本來就是深底淺線。深色不是風格選擇，是讓圖紙在畫面上成為最亮物件的功能性決定。
2. **量與價分離** —— 量測畫面絕不出現單價欄位。單價只存在於 SoR 造價核心。這條是業務契約，UI 必須讓它一眼可見。
3. **缺漏要吵** —— 缺單價、缺文件、缺圖號一律用 `--danger` / `--warn` 主動標示，不用「靜默通過」。缺漏是主角，不是附註。
4. **溯源不可藏** —— 每一筆量測、每一筆 SoR 都能追到圖號／比例／操作者／時間。溯源資訊放右側檢視器，不折疊、不藏進 modal。
5. **狀態完整** —— 每個畫面都必須有 空／載入／錯誤／降級 四態。只做 happy path 的畫面驗收不通過。
6. **密度優先** —— 這是專業工具不是消費產品。表格列高 34px、正文 14px、間距 4px 基準。寧可密，不要鬆。

## 3. 設計 Token

完整定義在 `tokens/vicons-tokens.css`，可直接 `<link>` 使用。重點：

### 3.1 底色四階（不准自創第五階）

| Token | 值 | 用途 |
|---|---|---|
| `--bg` | `#0a0e17` | 應用底 |
| `--panel` | `#121c2c` | 卡片／面板 |
| `--panel-2` | `#18243a` | 面板上的面板（表頭、選中列） |
| `--panel-3` | `#1e2c45` | 浮起層（下拉、modal body） |

### 3.2 文字三階（不准用純白）

`--ink #e8eefc` → `--ink-soft #a8b6cc` → `--ink-faint #6b7c96` → `--ink-ghost #46566e`

純白 `#fff` 在深底上會產生光暈並降低長時間閱讀舒適度。最高只用 `#e8eefc`。

### 3.3 狀態色

| 語意 | Token | 值 |
|---|---|---|
| 通過 / 就緒 | `--ok` | `#3ddc97` |
| 待處理 / 缺漏 | `--warn` | `#f0b429` |
| 錯誤 / 阻斷 | `--danger` | `#ff6b5b` |
| 品牌 | `--cobalt` | `#3b6ef0` |

### 3.4 造價色（中文慣例，與歐美相反）

```css
--price-up:   #ff6b5b;   /* 漲 = 紅 */
--price-down: #3ddc97;   /* 跌 = 綠 */
```

已在 harness 中以斷言鎖住，避免日後被改成歐美慣例。

### 3.5 字型與字級

- UI 字型：`Inter → Segoe UI → Microsoft JhengHei`（CJK 落點明確）
- 數字／代碼／量測值：`JetBrains Mono` + `font-variant-numeric: tabular-nums`
  **這條是硬性的** —— 表格數字不對齊等於不可比較。
- 字級基準 **14px**（不是 16px）。桌面專業工具偏緊，`--fs-2xs 10px` 到 `--fs-3xl 34px`。
- 大標題負字距 `-0.02em`，全大寫小標籤正字距 `0.08em`。

### 3.6 動效

`--t-fast 90ms` / `--t-base 150ms` / `--t-slow 220ms`。工程工具要求「快」，超過 220ms 就嫌拖。
`prefers-reduced-motion` 已全域處理。

### 3.7 版面尺吋

`--h-topbar 52px`、`--w-sidebar 236px`、`--w-inspector 340px`、`--h-row 34px`

### 4.1 表格的密度規則（重要）

```
列高 34px（--h-row）
表頭 10px 全大寫 + 0.06em 字距
數字欄一律 class="num" → 等寬 + 右對齊 + tabular-nums
可編輯格：hover 出邊框、focus 出 cobalt 環、缺值用 --warn 文字
缺漏列：tr.is-flagged → 左側 2px inset 黃條
```

### 4.2 空／載入／錯誤／降級

每個畫面都必須實作。`states` 畫面本身就是這四態的樣板，可直接對照實作：

- **空**：圖示 + 標題 + 說明 + 一到兩個明確行動。不要只寫「暫無資料」。
- **載入**：首選骨架屏（`.skel`），長任務用進度條 + 頁數 + ETA + 取消鈕。
- **錯誤**：必須給出**具體原因與可行動的下一步**，並附可複製的診斷明細。範例：圖紙無文字層 → 提供「改用 OCR 路徑」按鈕，並顯示文字密度實測值與門檻值。
- **降級**：功能部分不可用但**其餘照常**。範例：`file://` 開啟 → 直寫 IndexedDB 不可用，但下載 CSV 仍可用，並提示改用 `serve.py`。

### 4.3 無障礙

| 項目 | 實作 |
|---|---|
| 焦點環 | `:focus-visible` 2px `--cobalt`，offset 2px，全域 |
| 跳過導航 | `.skip-link`，鍵盤第一個停點 |
| 螢幕閱讀器 | `.sr-only` 工具類 |
| 停用控件 | 同時設 `disabled` 與 `aria-disabled="true"`，保留 tooltip 說明原因 |
| 動態區域 | toast host 用 `aria-live="polite"` |
| 當前頁 | 側邊欄用 `aria-current="page"` |
| 排序表頭 | 用 `aria-sort` |
| 減少動態 | `prefers-reduced-motion` 全域降為 1ms |

## 5. 畫面規格

已交付 9 個可點擊畫面。以下為各畫面的設計意圖與必備元素。

### 5.1 總覽 · 空狀態 `overview-1`

**意圖**：零專案時只給一條明確入口，不展示用不到的功能。

必備：四階段流程條（當前階段高亮）、拖放區、示範資料入口、「這個平台會做什麼」四條。
不應有：統計卡（數字全是 0，無意義）、空表格。

### 5.2 總覽 · 有資料 `overview-2`

**意圖**：一屏交代「現在該做什麼」。

必備：四張統計卡（專案數／待辦要求／SoR 條目／缺單價）、四階段流程條、最近專案表、待辦要求表（每列帶行動鈕）、右欄項目摘要 + 引擎狀態燈。

### 5.3 量測引擎 `takeoff`

**意圖**：畫布是唯一主角，chrome 全部讓位。

版面是**唯一 flush 型**：主區不滾動，iframe 撐滿。
左 = 工具列 + 畫布 + 底部狀態列；右 = 檢視器（條件清單／本頁合計／溯源／送往接口）。
必備：比例欄位帶「已確認」徽章、頁碼導航、損耗百分比可見、溯源含圖號／比例／單位制／操作者／時間。
**禁止**：任何單價欄位。

### 5.4 算量接口 `bridge`

**意圖**：讓「量測 → 造價」這一步完全透明可審計。這是最關鍵的畫面。

必備：四步驟條（匯入→解析→映射→落地）、三欄（來源／解析結果／落地選項）、映射預覽表、兩個解釋區塊。
映射表必須顯示：SoR 代碼、描述、單位、數量、單價（空白，placeholder「缺單價」）、溯源按鈕。
落地選項必須明示安全邊界：**替換模式只刪 `source = opentakeoff`**。

### 5.5 SoR 造價核心 `sor`

**意圖**：缺單價是主角。這一頁的存在意義就是逼你把價填完。

必備：四統計（含「已填單價 50%」比例）、篩選分段控件、12 列表格（可編輯單價格）、來源徽章（量測／Excel／手動）、缺漏列黃條標記、來源隔離回滾區、報價審查狀態三條。
數字對齊與等寬是硬性要求 —— 這是造價表，數字必須可逐列比較。

### 5.6 合規矩陣 `compliance`

**意圖**：把「到底還缺什麼」變成可逐項勾銷的清單。

必備：四統計、就緒度進度條、條款對應表（條款／名稱／要求／狀態／證據）、缺失項卡片（每項帶「建立事項」鈕）。
對應 HK GC Works Cl. 2 / 12 / 13 / 33 / 34，並含投標須知附表與 HA 感染控制要求。

### 5.7 提交清單 `output`

**意圖**：阻斷閘門。有硬性缺漏就必須擋住，不能讓使用者帶著缺漏產生提交包。

必備：**受阻時「產生提交包」按鈕必須 disabled** + 紅色閘門橫幅列出所有阻斷項、提交物明細表（狀態／名稱／類別／強制／檔案／頁數）、出圖規範四要素核對區。
出圖規範四要素（General Notes & Spec / Dimension & Detailing / Description / Scale）以四格標示齊備狀態，並顯示 `↑UP=LID` `↓DOWN=BASE` 標註規範。

### 5.8 MCP 服務 `mcp`

**意圖**：讓「版本釘死」與「安全邊界」可見，而不是藏在 README 裡。

必備：連線狀態卡（含「需到連接器管理頁按信任」的具體指引）、版本與來源卡（0.9.66、非浮動 latest）、安全邊界清單（四項不執行／不啟用的沙箱元件）、可複製的 `mcp.json` 片段、42 工具依用途分六組。

### 5.9 狀態樣板 `states`

**意圖**：交付用。這是實作時的對照表，不是給終端使用者看的畫面。

必備：空狀態 ×3、載入 ×3（骨架／統計卡骨架／長任務進度）、錯誤 ×2（含診斷明細）、降級 ×2、阻斷二次確認（含完整受影響清單）、權限／唯讀態、焦點環示範。

## 6. 合併後的模組邊界

合併為單一應用後，程式碼分層如下（維持零構建，用掛載點而非打包）：

```
vicons/
├── index.html              ← 唯一入口：外殼 markup + tokens + 元件 CSS
├── tokens/
│   ├── vicons-tokens.css       ← 只放變數
│   └── vicons-components.css   ← 只放組件
├── app/
│   ├── shell.js            ← 內核：DOM 建構器、路由、storage、toast、modal
│   ├── boot.js             ← 啟動：接線 + 首屏
│   ├── services/
│   │   ├── parse.js        ← 由 VicBid 遷入
│   │   └── export.js       ← 由 VicBid 遷入
│   ├── bridge/
│   │   ├── ot-vicbid-bridge.js      ← 原封不動搬入（已驗證 54 項）
│   │   └── ot-vicbid-report-bridge.js ← 原封不動搬入（已驗證）
│   └── views/              ← 每個檔案向 shell 註冊渲染函數
│       ├── overview.js
│       ├── takeoff.js
│       ├── bridge.js
│       ├── sor.js
│       ├── compliance.js
│       ├── output.js
│       ├── mcp.js
│       └── ...
└── engine/                 ← iframe 掛載點（OpenTakeoff dist-portable）
```

**約束**（沿用 VicBid 既有架構約定，該約定已被 129 項測試驗證）：
1. `shell.js` 只定義全應用共享的內核，供 views 直接呼叫。
2. **views 之間互不引用** —— 避免耦合與衝突。
3. 每個 view 檔向 `VC.registerView(id, meta, render)` 註冊。
4. 資料層用單一 IndexedDB `vicbid_db`，13 個 store 沿用既有 schema，不自創新 store。

## 7. 響應式

| 斷點 | 行為 |
|---|---|
| > 1280px | 完整三欄（sidebar + main + inspector） |
| ≤ 1280px | `grid--4` 降為 2 欄；`.split` 收成單欄；inspector 收起 |
| ≤ 1024px | sidebar 自動收合至 56px（只留圖示）；`grid--3` 降為 2 欄 |

**桌面優先已定**：最小支援寬度 1024px。低於此不保證可用（這是專業工具，不做手機版）。
